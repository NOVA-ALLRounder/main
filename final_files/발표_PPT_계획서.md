## 🖼️ 슬라이드별 세부 구성 계획

### 1. 도입 (2분)

#### Slide 1: 타이틀
- **헤드라인**: Steer — 사용자 행동 기반 자율 학습 AI OS 에이전트
- **서브 카피**: "컴퓨터가 당신의 습관을 학습하고, 스스로 자동화합니다"
- **발표 멘트**: 팀 Steer입니다. 저희는 LLM과 OS 네이티브 기술을 결합하여, 사용자의 행동을 관찰하고 자동화를 제안하는 에이전트를 만들었습니다.

#### Slide 2: 문제 정의 — 왜 지금인가?
- **핵심 메시지**: 기존 자동화 도구의 3대 한계
- **내용**:
  - ❌ **수동 설정**: 사용자가 직접 규칙을 정의해야 함 (UiPath, Zapier)
  - ❌ **플랫폼 제약**: 웹 브라우저만 제어 가능 (OpenAI Operator, Google Mariner)
  - ❌ **높은 비용**: 기업용 RPA 연 수십만 달러, AI 에이전트 구독 $2K~$20K/월
- **시장 데이터** (1~2개 핵심 수치만 언급):
  - 글로벌 RPA 시장: $4.68B (2025) → $25B+ (2030), CAGR ~30%
  - AI 에이전트 도입률 72%, 기업 52%가 GenAI 에이전트 프로덕션 배포
- **발표 멘트**: 자동화 시장은 폭발적으로 성장하고 있지만, 기존 도구들은 여전히 수동적이고, 브라우저에 갇혀 있고, 비쌉니다.

#### Slide 3: Steer의 해결책
- **핵심 메시지**: Steer의 3단 자율 프로세스
- **내용**:
  1. **Shadow** (관찰): 사용자 OS 사용 패턴을 백그라운드에서 자동 수집
  2. **Routine** (분석): 반복되는 행동 패턴을 AI가 스스로 감지
  3. **Control/Exec** (실행): 자연어 명령으로 OS 전체를 직접 제어
- **차별화 포인트**: "설정하지 않아도, 브라우저 밖에서도, OS 전체를 제어합니다."
- **발표 멘트**: Steer는 세 단계로 동작합니다. 먼저 사용자의 행동을 관찰하고, 반복 패턴을 스스로 발견한 뒤, 자연어 한마디로 OS 전체를 제어합니다.

> **전환 멘트**: "이 프로세스를 가능하게 하는 기술 구조를 보여드리겠습니다."

### 2. 기술 및 시스템 설계 (3분)

#### Slide 4: 기술 스택 — 왜 이 조합인가?
- **핵심 메시지**: 각 기술 선택의 이유를 한 줄로
- **내용**:

| 기술 | 역할 | 선택 이유 |
|------|------|----------|
| **Rust** | 코어 엔진 | 메모리 안전, 단일 바이너리, OS 네이티브 바인딩 |
| **GPT-4** | 자연어 이해 | Function Calling 안정성, 한국어 성능 |
| **Tauri** | 데스크톱 UI | Electron 대비 1/10 번들, Rust 직접 통합 |
| **n8n** | 워크플로우 | 셀프호스팅, 커뮤니티 생태계, API 유연성 |
| **SQLite** | 로컬 DB | 서버리스, 로컬 에이전트에 최적 |

- **발표 멘트**: 핵심은 Rust입니다. Rust를 선택함으로써 C++ 수준의 성능을 갖추면서도 메모리 안전성을 확보했고, macOS와 Windows 양쪽의 네이티브 API에 직접 바인딩할 수 있습니다.

#### Slide 5: 시스템 아키텍처
- **핵심 메시지**: 전체 데이터 흐름을 한눈에
- **내용 (간략화된 아키텍처)**:
  ```
  사용자 입력 (Desktop / Telegram / CLI)
       ↓
  API Server (Axum) → LLM Gateway (GPT-4)
       ↓
  Policy Engine (Zero Trust 보안 검증)
       ↓
  Executor (macOS: AppleScript / Windows: PowerShell)
       ↓
  Collector → SQLite → Pattern Analyzer → n8n 배포
  ```
- **강조 포인트**: LLM의 출력이 직접 실행되지 않고, 반드시 Policy Engine을 통과한다는 보안 아키텍처
- **발표 멘트**: 특히 주목해야 할 점은 LLM이 생성한 명령이 절대 직접 실행되지 않는다는 것입니다. 모든 액션은 반드시 Policy Engine의 보안 검증을 거칩니다.

#### Slide 6: 크로스 플랫폼 & 데이터 보안
- **핵심 메시지**: macOS + Windows 동시 지원 및 개인정보 보호
- **내용**:
  - **macOS**: Accessibility API 기반 이벤트 수집 + AppleScript 앱 제어
  - **Windows**: UI Automation API 기반 수집 + PowerShell/COM 앱 제어
  - **보안**: PrivacyGuard가 이메일/카드번호 등 PII를 실시간 마스킹
  - **보안 등급**: Safe → Warning → Critical 3단계 분류, Critical 작업 시 Write Lock
- **발표 멘트**: Steer는 macOS와 Windows 양쪽에서 동일한 경험을 제공합니다. 또한 수집되는 모든 데이터에서 개인정보는 실시간으로 마스킹됩니다.

> **전환 멘트**: "이제 실제로 어떻게 작동하는지 시연 영상으로 보여드리겠습니다."

### 3. 핵심 기능 시연 (6분)

> 전체 시연 영상을 4개 파트로 구성합니다. 각 파트 사이에 간단한 설명 슬라이드를 넣어 맥락을 전달합니다.

#### Slide 7: 시연 1 — Shadow & Routine (2분)
- **시나리오**: "매일 아침 같은 앱 3개를 열고 같은 작업을 반복하는 사용자"
- **시연 흐름**:
  1. Shadow가 백그라운드에서 사용자 행동을 수집하는 모습
  2. `routine` 명령으로 일일 패턴 분석 결과 확인
  3. AI가 "이 패턴을 자동화할까요?"라고 제안
  4. 워크플로우 자동 생성 및 n8n에 배포
- **핵심 포인트**: "사용자가 아무것도 설정하지 않아도 에이전트가 스스로 패턴을 발견합니다"

#### Slide 8: 시연 2 — Control (1.5분)
- **시나리오**: "자연어로 복합 앱 조작"
- **시연 흐름**:
  1. 사용자가 자연어로 명령 입력 (예: "Safari 열어서 구글에 날씨 검색해" / "슬랙에서 #general에 요약 보내줘")
  2. Steer가 앱을 열고, 클릭하고, 타이핑하는 과정
  3. Visual Driver 폴백 시연 (OS API 불가 시 화면 인식 기반 제어)
- **핵심 포인트**: "자연어 한마디로 실제 OS와 앱을 직접 제어합니다"

#### Slide 9: 시연 3 — Workflow & Exec (1.5분)
- **시나리오**: "자연어로 n8n 워크플로우를 생성하고 보안 셸 실행"
- **시연 흐름**:
  1. "내 다운로드 폴더의 CSV 파일을 정리해서 보고서로 만들어줘"
  2. LLM이 n8n 워크플로우 JSON을 생성
  3. Policy Engine이 Safe/Warning/Critical 분류 과정
  4. 안전한 명령은 자동 실행, 위험 명령은 사용자 확인 요청
- **핵심 포인트**: "자동화를 만들면서도 보안은 절대 타협하지 않습니다"

#### Slide 10: 시연 4 — Telegram 원격 제어 (1분)
- **시나리오**: "외출 중 모바일에서 OS 제어"
- **시연 흐름**:
  1. Telegram 봇에 자연어 명령 전송
  2. 집/회사 컴퓨터에서 명령 실행
  3. 실행 결과가 Telegram으로 자동 리포트
- **핵심 포인트**: "어디서든 내 컴퓨터를 제어할 수 있습니다"

> **전환 멘트**: "이 기술을 어떻게 사업화할 수 있을까요?"
