**Slide 7. 문제 제기 1 — "필요해서 찾아봤는데, 없더라"**

- **스토리텔링 흐름** (발표자가 자기 경험담처럼 말하기):
  1. "매일 같은 작업을 반복하고 있었다" — 로그인 → 데이터 조회 → 복붙 → 보고, 이런 단순 반복이 업무 시간의 상당 부분을 잡아먹고 있었음
  2. "그래서 자동화 도구를 찾아봤다" — RPA, 매크로, 자동화 플랫폼 등을 검색
  3. "그런데 현실은…":

| 찾아본 대안 | 문제점 |
|------------|--------|
| **기존 RPA** (UiPath, Automation Anywhere 등) | 연간 라이선스 수백~수천만 원, 대기업 전용, 도입 컨설팅까지 필요 |
| **매크로/스크립트** (AutoHotKey, Selenium 등) | 코딩 필수, 유지보수 어려움, UI 변경되면 다 깨짐 |
| **로우코드 플랫폼** (Zapier, Make 등) | 웹 서비스 간 연동만 가능, OS 레벨 자동화 불가 |
| **AI 어시스턴트** (ChatGPT, Copilot 등) | 조언은 주지만 직접 실행은 안 해줌, "말만" 하는 AI |

- 핵심 메시지: **"개인·소규모 환경에서 쉽게 쓸 수 있는, 실제로 '실행'까지 해주는 AI 자동화 도구는 없었다"**
- 비주얼 제안: 검색 → 벽(비용/복잡도/제한) → 좌절 → 💡 "그러면 우리가 만들자!" 전구 아이콘 전환
- 발표자 노트: _"저는 매일 30분씩 같은 작업을 반복하고 있었습니다. 분명 기술적으로는 자동화가 가능한 시대인데, 정작 개인이 바로 쓸 수 있는 도구는 없었어요."_

**Slide 8. 문제 제기 2 — "그런데 세상도 같은 생각이었다 (OpenClaw 현상)"**

> 💡 이 슬라이드가 발표 전체에서 **가장 강력한 설득 포인트** — "우리의 아이디어가 얼마나 시의적절한지"를 외부 증거로 입증

- **타임라인 스토리** (연대기 형태로 보여주기):

| 시점 | 일어난 일 | 의미 |
|------|----------|------|
| **2025년 12월 9일** | 🚀 **AllvIa 프로젝트 개발 착수** | 우리 팀이 "개인 AI 에이전트" 필요성을 독립적으로 인식하고 개발 시작 |
| 2025년 11월 | OpenClaw 오픈소스 첫 공개 (당시 주목도 낮음) | 비슷한 시기에 해외에서도 같은 문제의식이 존재했음 |
| 2026년 1월 | OpenClaw 바이럴 → **전 세계적 화제** | SNS·개발자 커뮤니티에서 폭발적 확산, "개인 AI 에이전트" 개념이 대중에게 각인 |
| 2026년 1~2월 | Mac Mini M4 **품절 대란** | OpenClaw를 24시간 돌리는 "AI 전용 머신"으로 맥미니 구매 폭주 → 전 세계 재고 소진 |
| **현재 (2026년 2월)** | "AI 에이전트" = IT 업계 최대 화두 | 빅테크·스타트업 모두 AI 에이전트 시장에 뛰어드는 중 |

- **왜 이게 중요한가** (3단 논리):
  1. "AllvIa 착수 (12/9) → OpenClaw 바이럴 (1월)" = **우리가 세상보다 먼저 움직였다**
  2. Mac Mini 품절 대란 = **AI 에이전트에 대한 수요가 '이론'이 아니라 '실구매'로 증명됨** — 사람들이 이걸 위해 하드웨어까지 사고 있음
  3. AI 에이전트 시장 급팽창 = **우리가 지금 만들고 있는 것이 정확히 시장이 원하는 것**

- **Mac Mini 품절이 의미하는 것** (보조 설명):
  - OpenClaw는 로컬에서 AI를 24시간 돌리는 구조 → 저전력·고성능 머신 필요
  - Mac Mini M4는 유휴 전력 ~5W, Apple Silicon SoC의 GPU/NPU 성능으로 최적의 "AI 서버"
  - 결과: 개인이 AI 에이전트를 위해 전용 하드웨어를 구매하는 현상 = **수요가 매우 구체적이고 강력함**

- 비주얼 제안: 가로 타임라인 + 각 시점에 아이콘/로고 (AllvIa 🚀 → OpenClaw 🌐 → Mac Mini 💻 → 🔥 현재)
- 발표자 노트: _"저희가 2025년 12월 9일에 개발을 시작했을 때, OpenClaw라는 이름은 들어본 적도 없었습니다. 한 달 뒤에 세상이 같은 아이디어로 난리가 났고, 맥미니까지 품절됐어요. 세상이 우리의 생각을 증명해준 셈입니다."_

**Slide 9. Solution — "그래서 우리가 AllvIa를 만들었다"**

- 헤드라인: **"All works, via AI"**

- **이름 해설 (비주얼: 글자가 분리·결합되는 애니메이션 추천)**:
  - **All** = 모든 업무, 모든 환경, 모든 사용자
  - **v** = via = ~를 통해 (라틴어)
  - **I** = Intelligence = 지능
  - **A** = Agent/AI = 에이전트
  - → 합치면: "모든 것을, AI 지능 에이전트를 통해" = **AllvIa**
  - 또는 간결하게: "All works, via AI — 모든 업무는 AI로 통한다"

- **AllvIa가 무엇인가 (한 줄 정의)**:
  > "사용자의 컴퓨터 사용 행동을 OS 수준에서 학습하고, 자연어 한 마디로 명령하면 스스로 반복 작업을 실행하는 **개인 AI 에이전트**"

- **AllvIa의 3대 핵심 원칙**:
  - 🧠 **Learn by Watching** — 가르치지 않아도 사용자 행동을 관찰하며 스스로 배운다
  - 💬 **Command by Speaking** — 코딩 대신 자연어로 "이거 해줘"라고 말하면 된다
  - 🔄 **Adapt by Itself** — UI나 환경이 바뀌어도 LLM이 맥락을 파악해 스스로 적응한다

- **기존 문제 → AllvIa의 해결 매핑** (문제제기 1에서 제기한 벽을 하나씩 허무는 구조):

| Slide 7에서 제기한 문제 | 왜 문제인가 | AllvIa의 답 | 어떻게 해결하는가 |
|----------------------|-----------|------------|------------------|
| 💰 비싸다 | RPA 라이선스 연간 수백~수천만 원 | 경량 · 오픈소스 기반 | 로컬 실행, 무거운 인프라 불필요, 커뮤니티 기반 업데이트 |
| 🔧 복잡하다 | 스크립트/플로차트 작성에 전문 지식 필요 | 자연어 명령 · 코드 불필요 | LLM이 사용자 의도를 해석 → 워크플로 자동 생성 |
| 💥 변경에 깨진다 | UI/프로세스 바뀌면 스크립트 전부 수정 | LLM 기반 자율 적응 | 화면 구조가 바뀌어도 LLM이 맥락을 재파악해 동작 조정 |
| 🚫 개인이 못 쓴다 | 대기업 전용, 도입 컨설팅 필요 | 개인~소기업 타겟 설계 | 설치 후 바로 사용 가능, 개인 PC 환경에서 동작 |
| 🤖 말만 하는 AI | ChatGPT는 답만 주고 실행은 안 됨 | OS 레벨 직접 실행 | 마우스·키보드·앱 제어까지 AI가 직접 수행 |

- 발표자 노트: _"문제제기에서 말씀드린 4가지 벽 — 비용, 복잡성, 취약성, 접근성 — 을 AllvIa가 어떻게 하나씩 허무는지 보여드리겠습니다."_

**Slide 13. SWOT 분석**

> 📍 **배치 근거**: SWOT은 **본론**에 두는 것을 권장합니다.

> - 결론에 두면 시연 영상 이후라 맥락이 끊기고, 결론은 "차별화·임팩트·미래"에 집중하는 것이 더 효과적

**[ Strengths — 강점 ]**
| 강점 | 상세 설명 |
|------|----------|
| **LLM 기반 자율 적응력** | 기존 RPA는 UI 셀렉터/좌표에 의존해 화면 변경 시 깨지지만, AllvIa는 LLM이 화면 맥락을 이해하므로 변경에 자율 적응 가능 |
| **경량·저비용 구조** | 무거운 서버/라이선스 없이 개인 PC에서 로컬 실행, 오픈소스 기반으로 도입 비용 0원에 가까움 |
| **코드리스 사용** | 자연어 명령만으로 자동화 설정 가능 → 비개발자도 즉시 사용, 러닝커브 최소 |
| **OS 레벨 학습** | 단순 웹 연동이 아닌, 사용자의 마우스·키보드·앱 전환 등 OS 행동 전체를 학습 → 범용 자동화 |

**[ Weaknesses — 약점 ]**
| 약점 | 상세 설명 | 대응 전략 |
|------|----------|----------|
| **초기 팀 규모** | 4인 팀으로 개발·운영·마케팅 동시 수행 부담 | 오픈소스 커뮤니티 빌드 → 외부 기여자 확보, 핵심 기능에 집중 |
| **학습 데이터 한계** | 다양한 업무 환경의 OS 이벤트 데이터 확보 어려움 | 얼리어답터 프로그램 → 실사용 데이터 수집, 사용자 피드백 루프 |
| **LLM 의존 리스크** | 외부 LLM API 가격·정책 변동에 영향받을 수 있음 | 로컬 모델(올라마 등) 지원으로 탈중앙화, 멀티 LLM 구조 설계 |

**[ Opportunities — 기회 ]**
| 기회 | 상세 설명 |
|------|----------|
| **AI 에이전트 시장 폭발적 성장** | OpenClaw 현상 + Mac Mini 품절 → 개인 AI 에이전트 수요가 "이론"이 아닌 "실구매"로 검증됨 |
| **RPA 미진입 영역 존재** | 기존 RPA는 대기업 중심 → 개인·프리랜서·소기업은 블루오션, 경쟁자 거의 없음 |
