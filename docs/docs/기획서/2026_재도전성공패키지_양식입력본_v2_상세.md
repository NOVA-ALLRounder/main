# 2026년 재도전성공패키지 사업계획서 양식 입력본 v2 (상세 완성본, docs+project 재검토)

## □ 과제 개요

| 항목 | 내용 |
|---|---|
| 과제명 | ALLVIA (가제 STEER OS) |
| 과제 한 줄 정의 | 로컬(macOS)에서 동작하는 OS 실행형 AI 에이전트의 실행 위험을 Zero-Trust 정책, 승인, 검증, 증빙으로 통제하는 실행 거버넌스 플랫폼 |
| 문제 정의 | 기업 자동화 도입의 핵심 장애는 기능 부족이 아니라 오작동, 권한사고, 감사 불가이며, 반복 업무 자동화 확산 시 누락/부분실패 비용이 증가 |
| 해결 방식 | Plan(LLM) -> Execute(Rust Core) -> Verify(Closed-Loop) 구조로 완료 신뢰성(Verified Completion) 제공 |
| 대상 플랫폼 | 1차: macOS 12+ / 2차: Windows 10+ (실행/수집 레이어 추상화 기반 확장) |
| 핵심 차별성 | Zero-Trust 5-Layer 실행 게이트, Closed-Loop Verification, Evidence Logging, Shadow Map 기반 루틴 승격 |
| 초기 고객 | Ops/BizOps/Growth Ops/CS Ops 팀, 고위험 워크플로우 보유 조직 |
| 협약기간 | 2026년 4월~10월 (7개월) |
| 정부지원 필요성 | 안전성/검증/증빙 체계를 선행 구축해 상용화의 전제조건(감사/통제) 확보 |

### 심사위원용 핵심 임팩트 문장

- ALLVIA는 단순 자동화 도구가 아니라, AI 실행을 승인·검증·증빙 가능한 수준으로 통제하는 기업형 실행 거버넌스 인프라입니다.
- 비개발자 조직(HR/운영/총무 포함)도 워크플로우 자동화를 즉시 활용할 수 있도록 설계해, 조직 전체 생산성과 인수인계 품질을 동시에 개선합니다.
- Zero-Trust 통제와 사용자 패턴 학습이 결합된 구조로, 초기 시장 점유 이후에는 운영 데이터 축적 효과로 대체 난도가 높아지는 방어적 경쟁력을 확보합니다.

## 1-1. 폐업 원인 분석 및 개선 방안

### A. 폐업 원인(구조적 진단)

1. CAPEX-리드타임-규모의 덫
- 시제품 -> 인증 -> 양산 -> 설치/운영까지 선투입 비용과 시간이 과도
- 일정 지연이 즉시 자금 리스크로 전이

2. 외부 의존성 고착
- OEM/설치 현장/규제/공급망이 사업 속도를 좌우
- 내부 실행력이 높아도 레퍼런스/매출 전환이 늦어짐

3. Time-to-Value 지연
- 고객 체감가치가 장기 편익 중심으로 나타나 계약 전환이 지연
- 손익분기점 이전 고정비 누적 가속

4. 성장 시 고정비 동반 증가
- 생산/물류/설치/AS 복잡도가 매출과 함께 증가
- 확장이 지렛대가 아닌 부담으로 작동

### B. 개선 방안(재발 방지 설계)

1. 사업 구조 전환
- CAPEX 중심 -> 소프트웨어(Local-first) 중심으로 전환
- 배포/개선 리드타임 단축, 고정비 경량화

2. 제품 핵심의 전환
- "자동화 기능" 중심이 아니라 "실행 통제/검증/증빙" 중심으로 설계
- 구매 포인트를 시간절감이 아닌 리스크 비용 절감(감사/사고/재작업)으로 재정의

3. 운영 통제 체계 내장
- Deny-by-default, Write Lock, Outbound Policy, Privacy Guard 기본값 적용
- Phase Gate + Kill Criteria로 KPI 미달 시 즉시 구조 수정/타깃 전환

4. 성공 판정의 정량화
- 완료 오판률, MTTR, 무승인 고위험 실행 0건, 전환율을 단계별 기준으로 관리

### C. 단계별 성공 판정(Phase Gate)

| 단계 | 핵심 질문 | 합격 기준 | 미달 시 조치 |
|---|---|---|---|
| Phase A (M1~M2) | 안전하게 실행 가능한가 | 정책 차단 정상률 향상, 무승인 고위험 실행 0건 | 정책/승인 UX 보강 |
| Phase B (M3~M4) | 실제 업무에서 신뢰 가능한가 | 완료 오판률 하향, MTTR 하향 | Assertion 확장 |
| Phase C (M5~M6) | 사용량이 전환으로 연결되는가 | 주간 runs 증가, 루틴 승인률 증가 | 추천 정밀도 개선 |
| Phase D (M7) | 조직 도입 요건 충족 여부 | 로그 보존/내보내기, 정책 프로파일 | 엔터프라이즈 패키지 강화 |

### D. Kill Criteria (중단/피벗 기준)

1. PoC에서 완료 오판률이 목표치 이하로 수렴하지 않을 경우
2. 고위험 워크플로우에서 승인 마찰로 사용자 이탈이 발생할 경우
3. 파일럿 -> 유료전환이 기준 미달일 경우

## 1-2. 재창업 아이템 목표시장(고객) 현황 및 필요성

### A. 시장/산업 환경

1. Agentic Automation 확산
- 자연어 -> 실행(클릭/입력/브라우저/셸) 흐름이 보편화

2. 기업 도입 장벽의 본질
- 자동화 자체보다 보안/감사/통제 부재가 실제 도입 저해 요인

3. 실험에서 통제로의 전환 시점
- 기능 구현만으로는 상용화 불가
- 검증 가능한 완료 + 실행 거버넌스가 도입의 선결 조건

4. macOS 로컬 우선 전략의 타당성
- Apple 엔드포인트 확대와 로컬 AI 워크로드 수요 증가
- Local-first + 프라이버시 보호 + 정책 통제가 시장 요구와 정합

### B. 고객 Pain Point

| 영역 | Pain Point | 기존 한계 |
|---|---|---|
| 반복 운영업무 | 누락/부분실패 발생 시 원인 파악 및 복구 지연 | 실행 성공 로그 위주, 검증 근거 부족 |
| 고위험 액션 | 외부 발신/권한/데이터 변경에 승인과 기록 필요 | 승인/감사 기능이 기본 제공되지 않음 |
| 자동화 신뢰도 | 완료 판정을 신뢰하지 못해 사람 재확인 필요 | ROI 저하, 확산 지연 |

### C. 초기 타깃 및 확장 타깃

- 1차 ICP: Ops/BizOps/Growth Ops/CS Ops(반복 업무 + 검증/증빙 니즈 높은 조직)
- 2차 ICP: 엔터프라이즈 IT/보안/컴플라이언스 조직, 규제 산업, MSP/컨설팅 채널

### C-1. 비개발자 수요 및 HR/기업 인수인계 적용성

- 워크플로우 자동화를 선제적으로 제공해, 코드 작성이 어려운 비개발자 조직에서도 즉시 도입 가능
- HR/총무/운영팀의 인수인계 업무를 루틴/워크플로우로 표준화하여 사람 의존 업무를 시스템 의존 업무로 전환 가능
- Zero-Trust 기반(승인 게이트, 정책 차단, 증빙 로그)으로 기업 내부 통제/감사 요구를 충족해 도입 저항을 낮춤

### D. 시장규모(TAM/SAM/SOM)

| 구분 | 정의 | 규모(예시) | 산출 논리 |
|---|---|---|---|
| TAM | 글로벌 RPA 시장 | $4.68B | 공신력 리서치 기반 |
| SAM | 온프렘/보안 친화 세그먼트 | $2.09B | 거버넌스/보안 수요 중심 |
| SOM | 1~2년 1차 목표 | KRW 5억~10억 | OEM 1개사 + Team/Enterprise 전환 |

- 도입 초기에는 안전한 자동화(Zero-Trust)와 승인/증빙 체계가 구매 의사결정의 기준으로 작동
- 도입 이후에는 사용자/팀별 실행 패턴(Shadow Map, 루틴 후보, 승인 이력)이 누적되어 운영 표준이 시스템에 내재화됨
- 시간 경과에 따라 추천 정밀도와 자동화 전환율이 함께 향상되어, 단순 기능 대체로는 같은 운영 품질을 재현하기 어려움
- 결과적으로 제품 전환 비용(재설정, 정책 재구축, 검증 체계 재적용)이 증가해 대체 난이도가 높아짐
