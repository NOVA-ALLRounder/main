# 2026년 재도전성공패키지 사업계획서 양식 입력본 v3 (제출 압축본, HWP 칸맞춤)

## □ 과제 개요

| 항목 | 내용 |
|---|---|
| 과제명 | ALLVIA (가제 STEER OS) |
| 한 줄 정의 | 로컬(macOS) OS 실행형 AI 에이전트의 실행 위험을 Zero-Trust 정책·승인·검증·증빙으로 통제하는 실행 거버넌스 플랫폼 |
| 문제 정의 | 자동화 도입의 핵심 장애는 기능 부족이 아니라 오작동·권한사고·감사 불가 |
| 해결 방식 | Plan(LLM) -> Execute(Rust Core) -> Verify(Closed-Loop) |
| 대상 플랫폼 | 1차 macOS 12+ / 2차 Windows 10+ |
| 핵심 차별성 | Zero-Trust 5-Layer, Write Lock, Verified Completion, Evidence Logging, Shadow Map |
| 초기 고객 | Ops/BizOps/Growth Ops/CS Ops, 고위험 워크플로우 보유 조직 |
| 협약기간 | 2026년 4월~10월 (7개월) |
| 정부지원 필요성 | 안전성·검증·증빙 체계 선구축으로 상용화 전제 확보 |

### 심사위원용 핵심 임팩트 문장

- ALLVIA는 단순 자동화 도구가 아니라 AI 실행을 통제 가능한 수준으로 표준화하는 실행 거버넌스 인프라이다.
- 비개발자 조직(HR/운영/총무 포함)도 즉시 적용 가능한 워크플로우 자동화를 제공해 인수인계 품질과 운영 생산성을 동시에 높인다.
- Zero-Trust 통제와 사용자 패턴 학습이 결합되어 도입 후 시간이 지날수록 대체 난도가 높아지는 구조다.

### 핵심 실증 KPI (협약기간)

| 지표 | 목표 |
|---|---:|
| 완료 오판률 | 5% 이하 |
| 무승인 고위험 실행 | 0건 |
| 평균 복구시간(MTTR) | 3분 이하 |
| 이벤트 유실률 | 0.1% 이하 |
| 주간 고객당 runs | 30 이상 |
| 파일럿 -> 유료전환률 | 30% 이상 |

### Why Now (시장/환경)

| 항목 | 수치/근거 |
|---|---|
| 글로벌 RPA 시장 | 2025년 $4.68B -> 2033년 $35.84B (CAGR 약 29%) |
| RPA 온프렘 세그먼트 | 2025년 $2.09B |
| Agentic AI 리스크 | 2027년까지 40%+ 프로젝트 중단 가능성 |
| 글로벌 PC 출하 | 2025년 270M+ 대 |

## 1-1. 폐업 원인 분석 및 개선 방안

### A. 폐업 원인(구조 진단)

| 원인 | 내용 |
|---|---|
| CAPEX-리드타임 병목 | 인증·양산·설치까지 선투입 비용/시간 과다 |
| 외부 의존성 | OEM/규제/현장 변수가 사업 속도 좌우 |
| Time-to-Value 지연 | 고객 체감가치 도달 전 비용 누적 |
| 확장비용 동반 증가 | 성장 시 고정비·운영복잡도 동시 증가 |

### B. 개선 방안(재발 방지 설계)

| 개선축 | 실행 방안 |
|---|---|
| 사업 구조 전환 | 하드웨어 중심 -> Local-first 소프트웨어 중심 |
| 제품 포지셔닝 전환 | 자동화 기능 중심 -> 실행 통제/검증/증빙 중심 |
| 운영 통제 내장 | Deny-by-default, Write Lock, Outbound/Privacy, Phase Gate |
| 정량 관리 | 오판률, MTTR, 무승인 실행 0건, 전환율 기준 운영 |

### C. 단계별 성공 판정(Phase Gate)

| 단계 | 핵심 질문 | 합격 기준 | 미달 시 조치 |
|---|---|---|---|
| Phase A (M1~M2) | 안전하게 실행되는가 | 무승인 고위험 실행 0건 | 정책/승인 UX 보강 |
| Phase B (M3~M4) | 실업무 신뢰가 확보되는가 | 완료 오판률·MTTR 하향 | Assertion 확대 |
| Phase C (M5~M6) | 사용량이 전환으로 이어지는가 | 주간 runs·승인률 상승 | 추천 정밀도 개선 |
| Phase D (M7) | 조직 도입 요건 충족 여부 | 보존/내보내기/정책 프로파일 확보 | 엔터프라이즈 기능 보강 |

### D. Kill Criteria (중단/피벗 기준)

1. 완료 오판률이 목표치 이하로 수렴하지 않을 때
2. 승인 마찰로 고위험 워크플로우 이탈이 지속될 때
3. 파일럿 -> 유료전환이 기준 미달일 때

## 1-2. 재창업 아이템 목표시장(고객) 현황 및 필요성

### A. 시장/산업 환경

1. Agentic Automation 확산: 자연어 -> 실행 흐름이 보편화
2. 기업 도입 장벽: 기능보다 보안/감사/통제 부족
3. 전환 구간: 실험 단계에서 통제 가능한 운영 단계로 이동
4. 전략 정합성: macOS 엔드포인트 확대 + 로컬 AI 수요 증가

### B. 고객 Pain Point

| 영역 | Pain Point | 기존 한계 |
|---|---|---|
| 반복 운영업무 | 누락/부분실패 복구 지연 | 실행 로그 위주, 완료 근거 부족 |
| 고위험 액션 | 외부 발신/권한/변경에 승인 필요 | 승인·감사 기능 기본 제공 약함 |
| 자동화 신뢰도 | 사람 재확인 필요 | ROI 저하, 확산 지연 |

### C. 목표 고객(ICP)

| 구분 | 대상 | 선정 이유 |
|---|---|---|
| 1차 ICP | Ops/BizOps/Growth Ops/CS Ops | 반복 업무 + 검증/증빙 니즈가 명확 |
| 2차 ICP | 엔터프라이즈 IT/보안/컴플라이언스, 규제 산업 | 정책·감사·보존 요구가 강함 |
| 3차 ICP | MSP/컨설팅 채널 | 고객사 확산 경로 확보 용이 |

### C-1. 비개발자 수요 및 HR/인수인계 적용성

- 워크플로우 자동화를 선제 제공해 비개발자 조직도 즉시 사용 가능
- HR/운영 인수인계를 루틴·워크플로우로 표준화 가능
- Zero-Trust 기반으로 내부 통제/감사 요건을 동시에 충족

### D. 시장규모(TAM/SAM/SOM)

| 구분 | 정의 | 규모(예시) | 산출 논리 |
|---|---|---|---|
| TAM | 글로벌 RPA 시장 | $4.68B | 공신력 리서치 기준 |
| SAM | 온프렘/보안 친화 세그먼트 | $2.09B | 거버넌스/보안 수요 중심 |
| SOM | 1~2년 1차 목표 | KRW 5억~10억 | OEM 1개사 + Team/Enterprise 전환 |
