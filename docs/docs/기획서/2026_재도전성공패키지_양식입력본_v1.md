# 2026년 재도전성공패키지 사업계획서 양식 입력본 (ALLVIA/STEER OS)

## □ 과제 개요
- 과제명: ALLVIA(가제 STEER OS)
- 아이템 정의: macOS 로컬 환경에서 OS 실행형 AI 에이전트의 실행 리스크를 Zero-Trust 정책, 승인, 검증, 증빙으로 통제하는 실행 거버넌스 플랫폼
- 해결 문제: 기업 자동화 도입 시 핵심 장애인 오작동, 권한사고, 감사 불가를 해결해 "검증 가능한 완료(Verified Completion)"를 제공
- 협약기간 목표: 2026년 4월~10월(7개월) 내 상용 PoC 완성, Design Partner 실증, 유료 전환 기반 확보
- 핵심 KPI(협약기간): 완료 오판률 5% 이하, 무승인 고위험 실행 0건, MTTR 3분 이하, 이벤트 유실률 0.1% 이하, 파일럿 유료전환률 30% 이상

- 폐업 시기: [입력]
- 폐업 사유 요약: 자본집약 구조, 외부 의존성(인증/공급망/파트너), 장기 리드타임으로 인해 매출 전환 전에 고정비 부담이 누적됨

## 1-1. 폐업 원인 분석 및 개선 방안
- 원인 1: CAPEX 중심 구조로 초기 투자와 운영비 부담이 과도했고, 일정 지연이 즉시 자금 리스크로 전이됨
- 원인 2: 파트너/인증/공급망 의존도가 높아 내부 실행력과 무관하게 사업 속도가 제한됨
- 원인 3: 고객이 체감하는 가치가 장기 편익 중심이라 Time-to-Value가 길어 계약 전환이 지연됨
- 개선 방안 1: 소프트웨어(Local-first) 모델로 전환해 리드타임 단축, 고정비 구조 경량화
- 개선 방안 2: 제품 핵심을 기능 확장에서 실행 통제/검증/증빙으로 설계해 기업 구매요건(감사/책임소재) 직접 충족
- 개선 방안 3: Phase Gate + Kill Criteria 운영으로 목표 KPI 미달 시 즉시 구조 수정/타깃 전환

## 1-2. 재창업 아이템 목표시장(고객) 현황 및 필요성
- 1차 고객: Ops/BizOps/Growth Ops/CS Ops 중심 조직(반복 운영 업무와 감사 요구가 높은 팀)
- 고객 문제: 자동화는 가능하나 실패 원인 파악, 승인 통제, 완료 증빙 체계가 약해 실제 확산이 막힘
- 시장 필요성: Agentic AI 확산과 동시에 보안/감사 요구가 강화되어 실행 거버넌스 수요가 빠르게 증가
- 진입 포인트: 고위험 워크플로우(외부 발신, 권한 변경, 데이터 변경)에서 "사고 방지 + 감사 증빙" 가치로 초기 계약 확보

## 2-1. 재창업 아이템 준비 현황
- 제품 아키텍처 준비:
  - Plan(LLM) -> Policy/Approval -> Execute -> Verify -> Evidence Logging 파이프라인 설계/구현
  - Zero-Trust 5-Layer(chat/policy/approval/outbound/privacy) 구조 확보
- 핵심 기술 준비:
  - deny-by-default, write lock, action classification(Safe/Caution/Critical)
  - closed-loop verification(Assertion 기반 완료 판정)
  - 로컬 데이터 파이프라인(이벤트 수집/요약/보존) 및 SQLite 운영 체계
- 제품화 준비:
  - 데스크톱 앱(Tauri), 로컬 API, 실행 엔진, 로그/승인 UX 기반 기능 검증 진행
  - PoC용 KPI 및 품질 게이트(회귀/보안 점검) 정의 완료

## 2-2. 재창업 아이템의 실현 및 구체화 방안
- 개발 전략: 7개월 내 MVP->PoC->제품화 단계로 진행
- 구현 범위:
  - M1~M2: 정책/승인/실행/검증 루프 완성
  - M3~M4: Design Partner PoC(업무 3종 시나리오) 및 KPI 개선
  - M5~M6: 루틴 추천->승인->자동화 승격 확장, 워크플로우 연동 고도화
  - M7: 엔터프라이즈 도입 요건(정책 프로파일/로그 보존/내보내기) 정리 및 최종 성과보고
- 실현 가능 근거: 기존 코드베이스와 명세 문서, KPI 기반 운영체계, 핵심 팀(코어/AI/프론트) 보유

## 3-1. 재창업 아이템 비즈니스 모델
- Track A(OEM 번들링, B2B2C):
  - PC 제조사 출하 이미지 프리인스톨 방식으로 설치 마찰 최소화
  - 대당 탑재비 기반 매출 + 확산 사용자 기반 확보
- Track B(Team/Enterprise 구독, B2B):
  - 좌석 + runs + 거버넌스 패키지(감사/보존/내보내기/정책 프로파일) 과금
  - 조직 도입 후 업셀 구조(팀 확장, 고급 정책, 엔터프라이즈 기능)
- 수익화 로직: OEM으로 확산, 구독으로 수익성(LTV) 확대하는 2-Track 구조

## 3-2. 재창업 아이템 사업화 추진 전략
- 고객개발: Design Partner 3~5개 조직 대상 4~6주 파일럿 운영
- 전환 전략: 파일럿 KPI 달성 기반 유료 전환 및 레퍼런스 확보
- 확산 전략:
  - 국내 제조사/Ops 팀 레퍼런스 확보 후 해외(미국/일본/싱가포르) 확장
  - 채널 파트너(컨설팅/MSP) 연계로 엔터프라이즈 도입 속도 확보
- 경쟁 대응: 기능 경쟁이 아닌 실행 통제/검증/증빙(Execution Governance) 우위 고도화
